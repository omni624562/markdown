section: 調整

- **重要操作改用系統對話框再確認一次**：把資料夾上傳成 GitHub 的公開儲存庫、把內容公開分享成 Gist、開啟 GitHub Pages 發佈網站，以及上傳時會換掉資料夾原本的遠端 origin，oMarker 都會先用系統的對話框說明會公開什麼、用哪個 GitHub 帳號，確認後才進行。
- **刪除專案**：勾選「同時把資料夾移到資源回收筒」時，除了輸入資料夾名稱，還會用系統的對話框顯示資料夾的完整路徑再問一次；選「否」就什麼都不動。
- **更換 Azure DevOps 伺服器**：連線到和之前不同的伺服器時，會先用系統的對話框確認；選「否」會保留原本的連線。第一次設定不會詢問。
- **重新開啟整合功能**：在設定把關掉的「Git 與 GitHub」、「Azure DevOps」或「遠端資料夾」重新打開時，會用系統的對話框確認；選「否」會維持關閉。
- **登入 GitHub**：在瀏覽器授權後，會用系統的對話框顯示要登入的帳號名稱，確認後才記住；選「否」就不登入。
- 這些系統對話框的預設按鈕都是「否」。GitHub 登入用的代碼也只留在程式內部，不再經過介面。
