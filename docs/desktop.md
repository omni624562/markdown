# 桌面版（Windows 免安裝）

**[下載最新版 omarker.exe](https://github.com/omni624562/markdown/releases/download/latest/omarker.exe)**（不需登入 GitHub），下載後直接執行，不需要安裝。也可以到 [Releases 頁面](https://github.com/omni624562/markdown/releases/latest)查看更新內容。

- 每次合併到 `main`，CI 都會自動更新這個「最新版」。
- 推送 `v` 開頭的標籤（例如 `v0.2.0`）時，會另外建立該版本的 Release。
- PR 的測試版放在 Actions 的 Artifacts（需登入 GitHub）。

- 介面和網頁版相同，開檔、存檔改用 Windows 原生對話框，`Ctrl+S` 會直接寫回原檔
- **開啟資料夾**：側邊欄的「檔案」會列出資料夾中的 Markdown、純文字與 JSON 檔（略過隱藏檔、`.gitignore` 排除的檔案與 `node_modules`）。可以新增檔案或資料夾、重新命名（開著的檔案也可以在分頁上雙擊或按右鍵「重新命名…」）、移到資源回收筒（可還原）、在檔案總管中顯示；也會記住最近開啟的資料夾，下次啟動自動開回來
- **多專案**（`Ctrl+Alt+P` 切換專案）：開過的資料夾都是專案。按左邊圖示列最上方的專案方塊（顯示專案的顏色與縮寫），或側邊欄上方的專案名稱，就能搜尋、切換專案；清單依「釘選」、群組、「最近開啟」分區。每個專案各自記住開著的分頁和檔案樹展開到哪裡，切換過去就回到上次的樣子；沒存的內容會留著，切回來還在，清單上也會標示「有沒存檔的分頁」。「專案總覽」用卡片列出所有專案，可以釘選、改名稱、設定顏色與群組（例如「公司」「個人」）、在檔案總管中顯示；卡片右下角的「刪除」（或「☰」→「專案」→「刪除專案…」刪除目前開著的專案）會跳出提示窗，要輸入專案的資料夾名稱才能刪除，預設只從清單移除，勾選「同時把資料夾移到資源回收筒」就連資料夾一起移到資源回收筒（可以從回收筒還原；系統與使用者資料夾、沒有資源回收筒的網路磁碟不會刪），目前開著的專案會先關閉；資料夾搬走時可以重新指定位置。釘選或有群組的專案會一直保留，其他的保留最近 30 個；從 GitHub、Azure DevOps 下載的儲存庫會自動放進對應的群組
- **新專案**（「☰」→「專案」→「新專案…」，或起始頁、專案切換器、專案總覽的「新專案…」）：在電腦上建立一個新資料夾當成專案開啟。填專案名稱（也是資料夾名稱）、選放在哪裡（預設是上次建立新專案的位置，第一次或那個資料夾不在了時是「文件」資料夾；「瀏覽…」可以換到別的資料夾），下面會寫出要建立的完整路徑；一開始放什麼：空白（只有一份 `README.md`）或筆記本（`README.md`、每日筆記資料夾、`assets` 圖片資料夾；每日筆記資料夾的名稱和設定裡的一樣）；可以勾選「同時建立 Git 儲存庫」（預設勾選，之後可以推送到 GitHub、Azure DevOps）與選專案顏色。按「建立並開啟」就切換到新專案、打開 `README.md`。名稱有 Windows 不能用的字元（`\ / : * ? " < > |`）、用「.」結尾或是保留名稱（`CON`、`NUL`、`COM1` 等）時馬上提示；同名的資料夾已經存在時不會建立，也不會覆蓋
- **COMET 專案**（「新專案…」對話框的「一開始放什麼」選「COMET 專案」那張小卡）：建立資料夾並設定好 COMET，不必面對終端機、也不必一題一題回答。對話框是左右兩張卡片：左邊「① 專案」，右邊「② COMET 設定」，右邊只有選了「COMET 專案」時能填，選「空白」或「筆記本」時變灰（填好的值留著）；上次選的小卡下次打開時預先選好。「② COMET 設定」：oMarker 已經連線 Azure DevOps 時，直接從清單選 Azure DevOps 專案、團隊與 Sprint（預設是目前的 Sprint，Sprint 天數從 Sprint 的日期算出來，可以改），「指派給」直接用 oMarker 登入 Azure DevOps 的帳號，不用填（只顯示一行「指派給　王小明（網域\帳號）　oMarker 登入的帳號」，要指派給別人時按「換人」，可以填姓名、完整帳號或員工編號），AreaPath 由團隊設定自動帶入；還沒連線時改成貼上 Sprint 工作板的網址。另外可以勾選「完成後查詢我的工作」（確認連得上 Azure DevOps）與「設定本機 PATH」（第一次使用 COMET 需要，就是把 `comet` 指令加進 PATH；`comet` 已經在 PATH 裡時預設不勾，旁邊註明「這台電腦已經設定過」。判斷時除了 oMarker 自己的 PATH，也看 Windows 記錄的使用者與系統 PATH，所以 oMarker 開著時才執行過 `comet setup` 也判斷得出來）。按「建立並設定」後，建立資料夾、切換到新專案、打開 `README.md`，接著用這些設定在背景執行 `comet setup --assume-yes`，對話框和填表時一樣寬：上面是目前的狀態，左邊「做了什麼」列出每一步，右邊「COMET 設定」列出這次用的 Azure DevOps 專案、團隊、Sprint（日期與天數）、指派給與資料夾，下面是 comet 的即時輸出；完成後下面那一格換成建立的檔案（`.comet.json`、`sprint-context.json`、`docs/spec/`、`AGENTS.md` 等，資料夾以 `/` 結尾），按「顯示完整輸出」在同一格切換。設定中、完成與失敗時對話框一樣大，不會跳動。等的時候可以按「在背景繼續」關掉對話框，完成時會跳出通知，按「查看」再看結果。失敗時對話框寫出原因、留著輸出，按「在終端機重試」改在下方的內嵌終端機一問一答（`comet setup` 的互動模式）。oMarker 已經存了 Azure DevOps 的 PAT 時，只有在 Sprint 網址或集合網址就是 oMarker 連線的那一台時，才在這次執行時用環境變數 `COMET_PAT` 交給 comet（不寫到檔案），第一次使用 COMET 不必先執行 `comet set-pat`。找 COMET CLI 時先找 PATH 裡的 `comet` 指令，沒有時再找安裝位置：先找 `%COMET_HOME%\bin\comet.exe`（安裝 COMET 時設定的環境變數），再找預設的 `%USERPROFILE%\Comet\bin\comet.exe`（第一次執行 `comet setup` 才會把 bin 資料夾加進 PATH，所以新電腦上 oMarker 會用完整路徑執行它；oMarker 不會自己改 PATH，讓 `comet setup` 照常幫你設定）。都找不到時（這台電腦沒裝 COMET）新專案對話框不列「COMET 專案」，也沒有右邊的「② COMET 設定」（只有左邊一張）。oMarker 啟動時檢查一次，視窗切回來、打開新專案對話框時再檢查，所以開著 oMarker 時裝好 COMET，切回來就會出現
- **認得出 COMET 專案**：資料夾裡有 `.comet.json`（做過 `comet setup`）的專案，在起始頁、檔案面板、專案切換器的名稱後面有淡綠色的「COMET」小標籤，專案總覽的卡片放在路徑下面那一行；開啟後側邊欄上方的專案名稱也有，左側圖示列的專案方塊右下角加一個綠點（滑鼠移上去會寫「COMET 專案」）。每次讀專案清單時檢查，所以剛做完 `comet setup` 的專案，重新打開清單就會出現標籤；遠端資料夾與網路磁碟上的專案不檢查
- **已經有的專案設定成 COMET 專案**：先建好專案、過一陣子才要用 COMET 時，開啟專案後按「☰」→「專案」→「設定成 COMET 專案…」（指令面板也找得到）。對話框只有「COMET 設定」一張，和新專案對話框右邊那張一樣（已經連線 Azure DevOps 時從清單選，還沒連線時貼上 Sprint 網址）；按「開始設定」後在專案資料夾背景執行 `comet setup --assume-yes`，進度、完成頁、「在背景繼續」與失敗時「在終端機重試」都和新建時一樣，只是沒有建立資料夾、Git 儲存庫這兩步。完成後專案名稱旁邊出現「COMET」小標籤。已經是 COMET 專案時，同一個位置改成「重新設定 COMET…」，用新的設定再執行一次（例如換 Sprint 或指派對象）。只有本機資料夾、而且這台電腦裝了 COMET 時才有這兩個項目；另一個 COMET 設定還在背景進行時，會請你等它完成再試
- **在 Codex 開啟這個專案**（「☰」→「專案」→「在 Codex 開啟這個專案」、指令面板，或專案切換器的「動作」）：用 Codex 桌面版開一個新對話，工作區就是目前專案的資料夾。oMarker 把資料夾組成 `codex://threads/new?path=…` 交給系統開啟，所以電腦上要先安裝 Codex 桌面版。只對專案清單裡的本機資料夾有作用，遠端資料夾（WebDAV、SSH）不會出現這一項。新版的 ChatGPT 桌面版把 ChatGPT 和 Codex 放在同一個程式，停在 ChatGPT 的聊天畫面時不一定會自己切到 Codex（外面也沒有辦法替它切換），所以開啟時的提示會寫：如果停在聊天畫面，請按左上角的「ChatGPT」切到「Codex」
- **把常用的功能釘到看得到的地方**：「☰」選單裡的項目按右鍵，選「釘到檔案面板上方」或「釘到左側圖示列」；已經釘了的換成「移除」。檔案面板上方的按鈕放在專案名稱那一列的最右邊（最多 3 個），跟著目前開著的專案：例如「在 Codex 開啟這個專案」的提示會寫出專案名稱，沒開專案時那一列不顯示，按鈕也一起不見；遠端資料夾、沒裝 Codex 時用不到的也會藏起來。上方有釘按鈕時，新增檔案、新增資料夾、重新讀取平常收起來，滑鼠移到檔案面板上才出現，專案名稱才有位置。釘上去的按鈕按右鍵可以移除。「在 Codex 開啟」用六角形圖示、「在 Claude Code 開啟」用星號圖示，分得出來
- **在 Claude Code 開啟這個專案**（「☰」→「專案」→「在 Claude Code 開啟這個專案」，就在 Codex 那一項下面；指令面板與專案切換器的「動作」也有）：在 Claude 桌面版的 Claude Code 開一個新的工作階段，工作目錄就是目前專案的資料夾。oMarker 把資料夾組成 `claude://code/new?folder=…` 交給系統開啟；從連結帶來的資料夾，Claude 一律先跳出確認對話框，按下確認後才會使用（就算之前已經信任過這個資料夾也一樣）。和 Codex 一樣只對專案清單裡的本機資料夾有作用
- **只在裝了桌面版時出現**：這台電腦沒有安裝 Codex 或 Claude 桌面版時，上面對應的那一項在「☰」→「專案」、指令面板與專案切換器都不顯示。Windows 上看系統有沒有登記開啟 `codex://`、`claude://` 網址的程式：一般安裝程式登記的 `HKEY_CURRENT_USER`／`HKEY_LOCAL_MACHINE` 的 `Software\Classes\codex`（或 `claude`）、Microsoft Store 版登記的套件網址（`…\AppModel\PackageRepository\Extensions\windows.protocol\codex`），或系統的檔案關聯（「預設應用程式」）查得到開啟的程式，任何一種找到就算有安裝；Linux 問 `xdg-mime`，macOS 一律顯示。oMarker 啟動時檢查一次，視窗切回來時再檢查（最多 5 秒一次），所以開著 oMarker 時裝好，切回來就會出現
- **左側圖示列的檔案捷徑**：常開的本機文字檔（例如 `D:\…\Notepad++\MENO.txt`、`週報.md`）可以放到左側圖示列：在檔案的分頁或檔案面板的檔案上按右鍵選「放到左側圖示列」（已經放了的是「從左側圖示列移除」），或把分頁、檔案面板的檔案拖到圖示列。捷徑和 Wiki 頁面一樣是檔名第一個字的彩色方塊，右下角的小標籤是副檔名（`txt`、`md`），一眼看得出是檔案；滑鼠移上去顯示完整路徑。按一下開啟（已經開著就切過去），檔案開在中間時，小圓點出現在副檔名標籤的右端。和 Wiki 頁面、工作項目的捷徑放在同一列、一起算上限（最多 12 個），不分專案，切換專案也都在；檔案不在目前的資料夾、很久沒開也開得了。檔案搬走或刪除時提示「找不到這個檔案」，通知上可以直接從圖示列移除；在 oMarker 裡改檔名時捷徑跟著換。只能放這台電腦上的檔案（遠端資料夾 SSH、WebDAV 的檔案不行）
- **在資料夾中搜尋與取代**（`Ctrl+Shift+F`）：可區分大小寫、使用正規表示式，點結果直接跳到那一行。按搜尋框左邊的箭頭展開取代欄，「全部取代」會先顯示要改幾個檔案、幾處再確認；取代前的內容會記在每個檔案的版本紀錄中，可以還原，有未存檔變更的分頁會略過（正規表示式可以用 `$1` 引用群組）
- **外部修改自動同步**：檔案被其他程式改過時（例如 NAS 同步軟體、另一個編輯器、Claude Code 等 AI 工具），沒有未存檔變更的分頁會自動重新載入（可按「復原」）；有未存檔變更時則提示你逐段比較差異。網路磁碟（`\\NAS\共用` 這類路徑）改用每 10 秒定時檢查，只檢查檔案樹會顯示的資料夾（略過 `.git`、`node_modules` 和 .gitignore 排除的資料夾，最多 2000 個）
- **版本紀錄**（「☰」→「文件工具」→「版本紀錄…」）：每次存檔都在本機留一份版本（每個檔案最多 50 份；超過 30 天的會清掉，但至少保留 10 份；超過 5 MB 的檔案不留版本；全部加起來超過 300 MB 時從最舊的開始清，每個檔案至少留最新一份；檔案刪掉超過 90 天後，它的版本也會清掉），覆蓋前檔案上的內容也會一起留下。選一個版本就能逐段比較，決定要採用哪些段落。紀錄存在 `%LOCALAPPDATA%\io.github.omni624562.markdown\history`，不會放進你的資料夾
- **網路磁碟最佳化**：`\\NAS\共用` 或對應成磁碟機代號的網路磁碟，讀寫都在背景進行，網路很慢時介面也不會卡住；超過 20 秒沒回應就停止等待，在編輯區上方提示「網路磁碟無法連線」，內容保留在編輯器裡，每 10 秒檢查一次，恢復後提醒你存檔
- **用 GitHub 同步（Git）**：Git 已經內建，不需要另外安裝，也不用輸入指令。
  - **登入**：設定 →「Git 與 GitHub」→「用 GitHub 登入」，在瀏覽器輸入畫面上的代碼授權即可；登入資訊存在 Windows 認證管理員
  - **下載儲存庫**（指令面板「GitHub：下載儲存庫…」）：從清單選一個儲存庫，選好放在哪裡，就會下載並開啟
  - **上傳到 GitHub**：把目前開啟的資料夾建立成新的儲存庫（可以選公開或私人）
  - **原始碼控制面板**：顯示分支、變更清單與數量，可以輸入說明後提交、拉取、推送（`Ctrl+Enter` 提交，指令面板也找得到）；檔案樹也會標示修改（M）、新增（U）等狀態
  - **拉取**：能快轉就快轉；兩邊都有新的提交時，改到不同地方會自動合併，改到同一個地方就放棄並維持原樣，不會留下衝突標記
  - **自動同步**：設定 →「Git 與 GitHub」可以開啟，每 5～60 分鐘提交、拉取、推送一次，出錯就暫停
  - **檔案的提交歷史**（指令面板「Git：這個檔案的提交歷史…」）：列出改過目前檔案的提交，選一個就逐段比較，可以把某幾段換回那一版
  - **在網頁上開啟／複製連結**（指令面板或右鍵選單）：開啟目前檔案在 GitHub 或 Azure DevOps 上的網頁，或複製連結；有選取文字時會標示行號（例如 `#L10-L20`）
  - **合併衝突逐段處理**：拉取時兩邊改到同一個地方，按通知上的「逐段處理」，在編輯器裡逐段選「採用遠端」或「保留本機」，存檔後按「完成合併」；也可以「放棄合併」回到原狀
  - **分支**：按原始碼控制面板上的分支名稱，切換分支、從遠端分支建立本機分支，或建立新分支（有未提交的變更時不能切換）
  - **建立 Pull Request**（面板標題列的 PR 按鈕）：在 main 上時先建立新分支，推送後在 GitHub 或 Azure DevOps 建立 PR
  - **發佈成網站**（指令面板「GitHub：發佈成網站（GitHub Pages）…」）：README.md 或 index.md 是首頁，之後推送就會自動更新
  - **分享成 Gist**（指令面板「GitHub：分享成 Gist…」）：把選取的內容或整份文件分享成秘密或公開的 Gist
  - **GitHub Issues**（側邊欄的圓點圖示，開啟連到 GitHub 的資料夾才出現）：列出還沒關閉的 issue，可以搜尋或輸入編號；點一下在主要區域顯示內容與留言（`Ctrl+F` 尋找）；在分頁上按右鍵可以「插入連結到目前的文件」（插入 `[#12 標題](網址)`）、「複製成 Markdown 文件」
  - 只支援 HTTPS 的遠端網址（GitHub 用登入的帳號；Azure DevOps 用個人存取權杖或 Windows 帳號；其他網站沿用電腦上 Git 已經存好的帳號），不支援 SSH。內建的 Git 不會執行儲存庫設定裡的外部程式，開啟別人給的資料夾也安全
- **Azure DevOps**：公司自架的 Azure DevOps Server 2019 以後與雲端版（dev.azure.com）都可以用。
  - **連線**：設定 →「Azure DevOps」輸入伺服器網址（集合網址，貼上專案或儲存庫的網址也可以）與個人存取權杖（PAT，權限勾選 Code 的 Read & write 與 Work Items 的 Read）；權杖存在 Windows 認證管理員
  - **下載儲存庫**（指令面板「Azure DevOps：下載儲存庫…」）：列出集合裡所有專案的 Git 儲存庫與專案 Wiki，選好放在哪裡就會下載並開啟；之後在原始碼控制面板提交、拉取、推送，和 GitHub 一樣
  - **上傳到 Azure DevOps**（原始碼控制面板在資料夾還不是 Git 儲存庫、或儲存庫還沒有遠端時的「上傳到 Azure DevOps…」，或指令面板「Azure DevOps：把這個資料夾上傳到 Azure DevOps…」、「☰」→「Git」）：先在本機建立的專案，之後也能放到 Azure DevOps。選 Azure DevOps 專案（只有一個時直接用），再選「建立新的儲存庫」（名稱預設是資料夾名稱，可以用中文和空白）或「用已經存在的空儲存庫…」（只列出那個專案裡還沒有任何分支的儲存庫，適合管理員先幫你建好的情況）。接著把資料夾設定成 Git 儲存庫（還不是時）、把遠端 origin 設成那個儲存庫、提交還沒提交的修改，再推送所有的檔案和版本紀錄；完成時的通知可以「在瀏覽器開啟」。資料夾原本已經有別的遠端 origin 時，會先問要不要換掉，選「否」就什麼都不做（也不會在伺服器上建立儲存庫）。建立新的儲存庫需要專案的「建立儲存庫」權限，個人存取權杖也要勾選 Code 的 Read, write, & manage；只有 Read & write 時，可以請管理員先建立空的儲存庫再選它。權杖只會送到連線的這台伺服器
  - **推送、拉取**：這台伺服器上的儲存庫會用個人存取權杖；權杖被拒絕而伺服器使用 Windows 整合式驗證時，會改用目前登入 Windows 的帳號。權杖與 Windows 帳號都只會送到連線的這台伺服器
  - **Wiki**（側邊欄的書本圖示，連線後才出現，和工作項目是分開的兩個圖示）：列出專案的 Wiki 頁面，可以搜尋頁面名稱與內容（篩選了最上層頁面或「只看這裡」時，只在顯示的範圍裡找，下面會提示藏了幾個最上層頁面），點一下在主要區域開啟，可以編輯（`Ctrl+S` 存回）、新增子頁面、刪除、查看修改紀錄，常看的頁面可以放到左側圖示列（按捷徑開啟時，側邊欄也換到 Wiki 或工作項目面板，看得到它在樹、清單上的位置；側邊欄收起來時不會自己開啟）。頁面的順序和網頁版的目錄一樣；在樹狀目錄把頁面拖到同一層的別的位置（放下的地方會畫一條線），或右鍵選單「往上移／往下移」、`Alt+↑／↓`，就調整頁面的順序（只限專案 Wiki；程式碼 Wiki 的順序寫在儲存庫的 `.order` 檔）。改名或搬移：右鍵選單（Wiki 樹或頁面的分頁）的「改名或搬移…」，或把頁面拖到別的頁面中間（搬進去當子頁面）、別層的前後，對話框確認新的名稱與放在哪一頁底下（子頁面一起搬）；勾選「一併更新其他頁面裡的連結」（預設勾選，會寫出有幾頁要改）時，搬移後把其他頁面裡連到它和子頁面的連結改到新位置（用頁面編號的完整網址不用改）。正在編輯的頁面要先存回並關閉才能搬；左側圖示列的捷徑會跟著換到新位置。右鍵選單（Wiki 樹或頁面的分頁）的「哪些頁面連到這一頁…」列出連到這一頁的頁面與那一行（相對、絕對路徑、同一個 Wiki 的完整網址都算），點一下開啟；刪除頁面前也會提醒哪些頁面連到這裡（刪除後這些連結會失效）。第一次要讀整個 Wiki 的內文，之後只讀改過的頁面。新增頁面時可以選範本：空白頁面、這個 Wiki 的範本（在 Wiki 最上層建立「範本」或「Templates」頁面，底下的子頁面就是大家共用的範本）、自訂範本或內建範本；範本裡的 `{{標題}}` 換成新頁面的標題，`{{日期}}` 等變數和文件範本一樣，每個 Wiki 記住上次選的範本。面板上方的「最近修改」（或指令「Wiki 最近修改…」）列出這個 Wiki 最近 30 次修改改到的頁面：哪一頁、新增／修改／刪除／改名、誰、什麼時候與修改說明，可以用頁面、人名或說明找，選一筆就開那一頁；篩選了最上層頁面或「只看這裡」時，和樹狀目錄一樣只列範圍裡的頁面。按面板標題列的「移到右側」（或圖示列右鍵「Wiki 放在右側」），Wiki 就固定在右側欄，和左邊的工作項目等面板同時開著（`Ctrl+Alt+B` 顯示／隱藏右側欄）；這時左側圖示列的 Wiki 圖示右邊有一條線，按一下就是「到 Wiki」：右側欄收著或 Wiki 那一區收合時打開，游標放進 Wiki 的搜尋框，不會收起整個右側欄
  - **工作板**（側邊欄的格狀圖示，和「工作項目」是分開的兩個圖示，連線後才出現）：Sprint 工作板，和 Azure DevOps 網頁的 Taskboard 一樣。側邊欄選專案、團隊、Sprint（預設是目前的 Sprint）與人員（所有人或只看我），主要區域開一個「工作板」分頁：每一列是一個上層項目（User Story、Bug…，可以收合；上層不在這個 Sprint 也會列出），每一欄是一個狀態（依工作項目類型的流程自動排），卡片上有編號、標題、指派對象與剩餘工時；沒有上層的工作放在最後一列「沒有上層」。**拖曳卡片到別的欄就是改狀態，拖到別的上層那一列就是換上層**（拖到「沒有上層」那一列是移除上層；別人剛改過時會提示，不會蓋掉）；點卡片在同一個分頁開啟工作項目，按 `<` 或 `Alt+←` 回到工作板。狀態列顯示工作數量、剩餘工時與 Sprint 結束日
  - **工作項目**（側邊欄的看板圖示，連線後才出現）：預設列出指派給你、還沒結束的工作項目
    - **搜尋與篩選**：搜尋會找標題與內容（說明、重現步驟、驗收條件），也可以輸入編號。篩選列可以依人（指派給我、我建立的、所有人，或輸入名字找指派給某人或某人建立的）、狀態（選的專案、類型實際用得到的狀態，例如 New、Active、Resolved、Closed，可以只看某幾個；勾的剛好是所有還沒結束的狀態時按鈕寫「進行中」，新增的狀態也算進去）、類型、專案與區域篩選（篩選一直顯示在清單上面：專案在最上面一整列，有條件時右邊的 × 一次清掉；下面是人與區域（選了專案才有區域）、類型與狀態，最後是搜尋框）；狀態、類型、專案、區域都可以複選，第一列「全部」一次勾選或取消全部，滑鼠移到某一項時按「只選這個」只留那一項，選項多時可以打字找；勾好後點外面（或按 Esc、Enter）就套用，不會每勾一個就查一次。和預設不同的條件，按鈕會用強調色標出來
    - **收合篩選區**：工作項目、Wiki 面板標題列最左邊的收合按鈕（↕）把上方的篩選區收起來，清單多一點空間：工作項目換成一行目前的條件（例如「所有專案 · 指派給我 · 所有類型 · 進行中」），Wiki 換成一行目前的 Wiki 名稱（Wiki 選單、新增頁面、搜尋框都收起來）；按一下那一行或再按一次按鈕就展開。兩個面板各自記住；從圖示列打開右側的 Wiki、游標要放進搜尋框時會自動展開
    - **清單**：搜尋框與篩選固定在上面，只有清單捲動；可以依上層項目分組：排成一棵樹（Epic → Feature → User Story → Task），每一項只出現一次，在它的上層底下，同一層依編號由小到大排，每一層往右縮一點、左邊有線連起來；不是指派給你的上層也會列出來當標題（淡色），標題下面寫底下有幾個 Story、幾個 Task。沒有上層的項目也是最上層的一列（例如底下的項目都不是你的 Epic），最上層依 Epic、Feature、Story、Task 的順序排。也可以依區域分組：篩選選了區域時一個區域一組（順序和區域選單一樣），子區域的項目放在上層區域那一組，列上的小字旁邊標出子區域（例如 IRIS 那一組裡標「監控」，滑鼠移上去看完整的區域）；沒選區域時依專案底下的第一層區域分組，直接在專案底下的是專案名稱那一組，列出好幾個專案時標題前面加上專案；更新前存下的離線資料沒有區域，先放在最後的「其他」，重新整理後就會分好。也可以依區域＋上層項目分組：外層和依區域分組一樣一個區域一組（順序、標題、數量、子區域的小字都一樣），組裡再和依上層項目分組一樣排成樹，只用這一組的項目；上層在別的區域時（例如 Task 在 Cobalt、它的 User Story 在 IRIS），User Story 淡淡地列在 Cobalt 那一組當上層，Task 只出現在 Cobalt，所以同一個上層可能在好幾組各淡淡地出現一次，組的數量只算這一組自己的項目；組和樹的每一層都可以收合，各收各的。列的項目和依區域分組一樣（依上層項目分組會另外補上清單只取最近更新的 100 個而沒列到的子項目，這個排法不補）。一鍵全部收合（只剩最上層）或展開；從別的地方開啟某一項時，清單會展開它的上層。每一列左邊有一條類型顏色的色條（和分頁圖示同色），狀態在右上角，前面的圓點依狀態上色（新的灰、進行中藍、已解決橘、已完成綠），一眼看得出是哪種項目、做到哪裡
    - **一起改好幾個**：`Ctrl`＋點一下加選、`Shift`＋點一下選一段，或按清單上方的勾選圖示進入選取模式（點一下就是選取）。選了之後上方出現「一起改…」：狀態（只列選的類型都有的狀態）、指派給我或取消指派、優先順序、Sprint（選的都在同一個專案時），也可以一起加一則留言；只改有選的欄位，一個一個送出，最後說改好幾個、哪幾個沒改成（和原因）。`Esc` 或「取消選取」離開
    - **內容**：點一下就在中間的主要區域開啟，和 Azure DevOps 網頁看起來有區別——上方是類型、標題與一排小標籤（狀態、指派給、優先順序、Sprint、更新時間），下面一行是專案與區域、建立者、標籤，說明、重現步驟、相關工作項目、附件、留言各是一張可以收合的卡片（「全部收合」一次收起來，收合狀態會記住）。留言是有頭像的對話卡片，顯示「3 天前」這樣的時間，上次看過之後的新留言標「新」；最新的幾則展開、較舊的收成一行，很長的留言先顯示前面一段，可以切換最新或最舊的在上面
    - **加入附件**：附件段落的「加入附件…」可以一次選好幾個檔案；也可以直接把檔案拖到工作項目上（放開時提示「放開以加入附件」）。在說明、驗收條件、留言的編輯框貼上截圖，會上傳成附件並在游標位置插入圖片，存檔或送出後在 Azure DevOps 網頁上一樣看得到。單一檔案最多 60 MB（Azure DevOps 預設的上限）
    - **附件**：每個附件一個小方塊（檔名、大小、上傳時間，圖片有縮圖），點小方塊直接開——文字檔在 oMarker 開成唯讀分頁、圖片在 oMarker 裡放大、PDF、Word／Excel／PowerPoint 文件（DOCX、XLSX、PPTX、DOC、XLS、PPT）與 ZIP 下載後用 Windows 預設的程式開啟；每個附件都可以「另存新檔」。為了安全，其他類型（.exe、.rdp、.msc、有巨集的 .docm／.xlsm、沒有副檔名的檔案等）只能另存，點小方塊或內文裡的連結會改成另存新檔或提示另存。檔案類型照 Windows 實際存檔的方式判斷（檔名結尾的點和空白不算、只看最後一個副檔名，檔名有冒號的不直接開啟）。直接開啟或另存的附件都會標上「從網際網路下載」（Mark of the Web），Office 文件會先用「受保護的檢視」開啟
    - **標籤與檔案**：內文裡「AI-CodeGen / Copilot / Claude」這種用斜線隔開的標籤行顯示成彩色小標籤；單獨一行的檔案路徑顯示成檔案方塊，有同名的附件時點一下就開那個附件
    - **分頁**：工作項目、Wiki 頁面、GitHub issue 和文件一樣開成分頁，點分頁就在文件與工作項目之間切換（`Esc` 或狀態列的「回到文件」也會回到文件，工作項目的分頁留著）。從側邊欄的清單、`Ctrl+P` 或圖示列的捷徑開的，每一項各自一個分頁（已經開著就切過去）；在分頁內容裡點連結（不管連到 Wiki 頁面還是工作項目）都留在同一個分頁，用上一頁（`<`、`Alt+←`）回來。新的分頁開在目前分頁的右邊；可以釘選，右鍵選單、`Ctrl+Tab`、`Ctrl+Shift+T`（重新開啟剛關的分頁）、`Ctrl+P` 都和文件的分頁一樣。內容裡的連結在同一個分頁往下走，可以按「←」回上一頁。工作項目與 Wiki 頁面的分頁下次開啟時還在。切到分頁時，左邊的工作項目清單或 Wiki 樹會標出它的位置（展開上層、捲過去），和檔案面板一樣。Wiki 頁面按「編輯」時在同一個分頁切成編輯（`Ctrl+S` 存回 Wiki），編完按狀態列的「完成編輯」換回閱讀
    - **分頁看得出是哪一項**：工作項目的分頁名稱前面有編號（例如「1922925 Design：定義需求」），圖示用類型的顏色（Bug 紅、Task 黃、User Story 藍、Feature 紫、Epic 橘…）；Wiki 頁面的分頁，滑鼠移上去顯示完整位置（例如「P.wiki › 產品 › 安裝」）。類型的顏色可以在「設定 → Azure DevOps → 工作項目類型的顏色」改：點色塊挑顏色，改過的按 × 恢復預設；分頁、清單的色條、工作項目上方的類型標籤、左側圖示列的捷徑一起換（捷徑整塊塗上類型的顏色，字自動用白色或深色）。左側圖示列上，上面的面板圖示亮著（左邊一條＋底色）表示側邊欄開著哪個面板；捷徑右下角的小圓點表示這個內容正開在中間（檔案捷徑的小圓點在副檔名標籤的右端），開著的捷徑再按一次捲回最上面。列出的是伺服器上有的類型，公司自訂的類型（預設灰色）也可以設
    - **內容裡的連結**：都在 oMarker 裡開，不會跳到瀏覽器。
      - Wiki 頁面裡的相對連結（`子頁面`、`../其他頁面`）會開那一頁：先在同一層找，找不到再當成這一頁底下的子頁面。
      - 連到工作項目、Wiki 頁面的完整網址也在 oMarker 裡開；網址只寫電腦名稱、http／https 或埠號和連線設定不同也認得。
      - 工作項目、Wiki 頁面內容裡寫成 `#編號` 的文字（例如表格裡的 `#1940122`、留言裡的「Story #1895964 / Task #1895969」）會變成工作項目連結：滑鼠停一下顯示摘要（類型、標題、狀態、指派給誰），點一下在 oMarker 開啟。先問過伺服器有這個工作項目才換；兩位數以下（條列的「#1」「#12」）、程式碼裡、段落標題列與標題裡的不換。GitHub Issue 與自己的 Markdown 文件不換。
      - Wiki 儲存庫裡的文字檔（例如 `.json`、`.yaml`）開成唯讀分頁；`#標題` 捲到這一頁的那個標題。
      - 找不到的頁面只會提示「找不到連結的頁面」；只有其他網站的網址才用瀏覽器開。
    - **畫面**：狀態列右邊顯示狀態、留言數、附件數、相關項目數與最後更新時間。在工作項目的分頁上按右鍵 →「在文件右邊並排顯示」改成文件在左、工作項目在右，邊看邊寫（這時右半邊被工作項目佔住：按「預覽」會在左半邊顯示文件的預覽，「分割」當成即時預覽）；再點一次取消勾選就回到佔滿整個區域
    - **直接修改**：在哪裡看到就在哪裡改。標題下方的狀態、指派、優先順序、Sprint 小標籤點一下出現選單（狀態列出這個類型可以設定的狀態；指派可以「改成指派給我」；Sprint 分成目前與之後、沒有日期、過去的，目前的標「（目前）」）；標題滑鼠移上去出現鉛筆（或雙擊標題）就能改，`Enter` 存、`Esc` 取消；標籤滑鼠移上去有 × 可以移除，最後面的「＋ 標籤」可以新增（逗號隔開可以一次加好幾個）。說明、驗收條件（Bug 是重現步驟）的段落標題列有「編輯」，在卡片裡用 Markdown 改，`Ctrl+Enter` 儲存、`Esc` 取消；圖片、清單、表格都會保留，有文字顏色、字型或合併儲存格時會先提醒（存回後變成一般格式）。改到一半切到別的分頁再回來，還沒存的內容會接著顯示；還沒有內容的段落也會列出來，可以直接新增。留言框在「留言」段落的最上面，點一下展開，可以用 Markdown，`Ctrl+Enter` 送出。打 `@` 跳出同事清單（先列專案預設團隊的成員，打了字再到伺服器找團隊以外的人），`↑` `↓` 選、`Enter` 或 `Tab` 確定，送出後對方會收到通知，和網頁版的 @ 一樣；編輯自己的留言時原本的 @ 會保留。「相關工作項目」段落的標題列有「加入關聯」：選上層（已經有上層時是「換上層」）、子項目、相關、前置項目或後續項目，再輸入標題關鍵字或編號找工作項目；每個關聯滑鼠移上去後面有 ×，問過之後只拿掉關聯，工作項目本身不會刪除。每次只送出改的那一項，開啟之後被別人改過時會提醒重新整理，不會蓋掉別人的修改
    - **修改紀錄**：工作項目上方的「修改紀錄」按鈕列出每一次修改：誰、什麼時候，改了哪些欄位（原本 → 之後；說明等長文字只標出有修改）、加了或移除哪些關聯與附件、加了什麼留言，最新的在前面。開在同一個分頁，按上一頁回到工作項目
    - **動作**：上方只留上一頁、下一頁與在瀏覽器開啟、尋找、重新整理；工作項目的類型標籤與編號也在這一列（和標題對齊），往下捲到看不到標題時，這一列會帶出標題；Wiki 頁面也一樣：這一列是位置（Wiki › 上層頁面），頁名只在內容最上面大字顯示一次（內容沒有同名的大標題時自動補上），往下捲時位置縮成「… › 上一層」、後面接著頁名，按頁名捲回最上面；`Ctrl+F` 在內容中尋找，也可以在瀏覽器開啟。少用的動作在分頁的右鍵選單：「插入連結到目前的文件」（在游標位置插入 `[#123 標題](網址)`；也可以直接把清單上的項目拖進文件）、「放到左側圖示列」、「複製成 Markdown 文件」（開成可以編輯的分頁）、「保留離線」，Wiki 頁面另有「新增子頁面」、「改名或搬移」、「哪些頁面連到這一頁」、「刪除這一頁」
- **WebDAV 遠端資料夾**（「☰」→「專案」→「連線到遠端資料夾」，或沒開資料夾時檔案面板的「連線到 WebDAV」）：直接開啟 Synology、QNAP、Nextcloud 等 NAS 上的資料夾，不需要先掛載成網路磁碟。可以瀏覽、開啟、存檔、新增、重新命名、刪除（遠端沒有資源回收筒，會先確認）、貼上圖片，預覽也會顯示遠端圖片。每 30 秒檢查已開啟的檔案有沒有被其他電腦改過；存檔時用 ETag 確認，被改過就先詢問，不會蓋掉別人的修改。密碼可以選擇存在 Windows 認證管理員；為了安全，預設只接受 HTTPS，只有區域網路的位址在你確認後才能用 HTTP
- **SSH 遠端資料夾**（「☰」→「專案」→「連線到遠端資料夾」，或沒開資料夾時檔案面板的「用 SSH 連線」）：直接開啟 Linux 主機（伺服器、NAS、樹莓派）上的資料夾，功能和 WebDAV 相同（瀏覽、開啟、存檔、新增、重新命名、刪除、貼上圖片、外部修改提示、存檔衝突處理）。主機欄可以直接輸入 `帳號@主機:連接埠`；密碼留空時用 ssh-agent（Windows 的 OpenSSH 驗證代理或 Pageant）或 `~/.ssh` 裡的金鑰登入，也可以指定金鑰檔（只接受這台電腦上的完整路徑，不接受網路路徑）。第一次連線會用系統的對話框顯示主機金鑰的演算法與指紋請你確認，記在 `~/.ssh/known_hosts`（和 ssh 指令共用，只記那台主機的那個連接埠），金鑰變了會拒絕連線。經由跳板主機（「進階」→「跳板主機」）時，兩台分開確認；跳板主機只用金鑰或 ssh-agent 登入，需要密碼時會另外詢問跳板主機的密碼，不會送出目標主機的密碼。修改已儲存連線的跳板主機或金鑰檔時，會重新詢問密碼。網路斷掉後會自動重新連線。開著 SSH 資料夾時，內嵌終端機會直接登入同一台主機、切換到那個資料夾（使用系統的 ssh，Windows 10 以後內建）
- **內嵌終端機**（``Ctrl+` ``，或「☰」→「AI 與終端機」→「顯示／隱藏終端機」）：在下方開啟 PowerShell，工作目錄是目前開啟的資料夾；可以開好幾個分頁。輸出中的網址按住 `Ctrl` 點一下，就會用預設瀏覽器開啟（例如 Claude Code 開好的 PR 連結）
- **自動更新**：每天檢查一次 GitHub 上的最新版，有新版時詢問，下載並核對數位簽章與檢查碼後替換執行檔（只接受用正式私鑰簽過的版本），重新啟動即完成（設定 → 進階可以關閉，或手動「檢查更新」）。**更新管道**（設定 → 關於）：預設是「穩定版」，只更新到維護者在 GitHub Actions 用「設為穩定版」選定的版本；改成「搶先版」則每次修改後都會收到新版。還沒有設定過穩定版時，穩定版會先跟著搶先版。自己編譯的版本不會自動更新。下載時先用 Windows 內建的連線方式（和瀏覽器一樣照 Proxy 設定、自動設定指令碼 PAC 與 Windows 帳號驗證），速度和用瀏覽器下載差不多；連不上時才改用另一種方式
- **回報問題**：「設定」→「關於」的「複製版本資訊」把版本、更新管道、第幾次建置、Windows 版本（分得出 10 和 11）與 WebView2 的版本複製到剪貼簿；「回報」（或「☰」→「說明」→「回報問題或建議」）開 GitHub 的新問題時，內文已經放好這些資訊，前面有一段註解提醒這是公開的頁面，不要貼公司的文件、帳號或內部網址。只有版本與系統資訊，不含檔案或帳號
- 可以把 `.md`／`.txt`／`.json` 檔或資料夾拖到 `omarker.exe` 上開啟，或在「開啟檔案」中設定成預設程式。編輯器已經開著時，再開其他檔案會在原本的視窗開成新分頁，不會多開一個視窗
- **最近開啟的檔案**（「☰」→「最近開啟的檔案…」或 `Ctrl+R`）：最近的 10 個檔案；開過的資料夾都是專案，在起始頁、切換專案與專案總覽
- **檔案面板（沒開資料夾時）**：最上面是最近的專案（和起始頁同一份清單，用自訂的名稱與顏色，名稱下面一行是位置；記住的 WebDAV、SSH 連線也列在這裡，標上「WebDAV」「SSH」），右上角的「全部專案」開啟專案總覽；接著是「開啟資料夾…」「新專案…」；最下面的「其他方式」有 GitHub、Azure DevOps 下載儲存庫（名稱下面註明帳號或還沒登入／還沒連線）、連線到 WebDAV、用 SSH 連線。還沒有任何專案時，最上面改成一句說明
- **編碼與換行**：開檔時依 BOM 認出 UTF-8、UTF-16，沒有 BOM 又不是 UTF-8 的舊檔案用 Big5 讀取。存檔時照原本的編碼、換行（CRLF／LF）與 BOM 寫回，Big5 的檔案存檔後還是 Big5。狀態列顯示檔案的編碼與換行：
  - 按編碼可以「用其他編碼重新讀取」（畫面上是亂碼時，例如其實是 Shift_JIS、GB18030 的檔案），或換「存檔時用的編碼」（UTF-8、UTF-8 含 BOM、UTF-16、Big5…），選了馬上存一次。

  - 遠端資料夾（SSH、WebDAV）的檔案一律存成 UTF-8（不是 UTF-8 的檔案開啟時會提示）。

## AI 協作（預設關閉）

在「設定 → AI 協作」（或「☰」→「AI 與終端機」→「AI 協作設定…」）開啟；第一次偵測到電腦上有安裝 Claude Code 或 Codex 時，也會提示一次。使用你自己安裝並登入的 [Claude Code](https://code.claude.com) 或 Codex，編輯器不會儲存任何帳號或金鑰；AI 提出的修改**一律先逐段標示差異，由你決定是否套用**，接受後也要自己存檔。

- **在終端機啟動 Claude Code／Codex**：「☰」選單或終端機面板上的按鈕會直接啟動，並自動連上編輯器
- **把選取範圍傳給終端機中的 AI**（`Ctrl+Alt+J`，或選取文字後浮出按鈕中的終端機圖示）：把 `@週報/十月.md#L3-8` 這樣的檔案與行號參照貼到 Claude Code／Codex 的輸入列，接著直接打字問它；沒有選取時傳整份文件。還沒開 AI 時會先啟動，有未存檔的變更會先存檔（AI 讀的是磁碟上的檔案）
- **讓 AI 在終端機執行指令**：AI 可以要求在編輯器的終端機執行指令（例如 `git log`、`pandoc` 轉檔、建置），**每次都會先跳出對話框讓你同意**（預設選在「拒絕」，打字時跳出來也不會誤按），同一個指令要重複執行時，可以選「這次開啟期間，這個指令都直接執行」（只限一模一樣的指令與執行位置，AI 改要求別的指令時仍然會先問）。對話框會折行顯示完整的指令；指令只能是一行，含有換行或看不見的特殊字元（例如改變文字方向的控制字元、零寬字元）時不會執行。執行過程顯示在新的終端機分頁，結束代碼與輸出會回覆給 AI；AI 也能讀取終端機分頁的輸出（例如你看到的錯誤訊息）。可以在設定中關閉
- **讓 AI 讀取目前的文件**（編輯器 MCP 伺服器）：AI 可以讀取你正在看的文件、選取範圍與已開啟的分頁，並用 `propose_edit` 提出修改；編輯器顯示差異，你接受或拒絕後，結果會回覆給 AI。伺服器只接受本機連線，而且需要權杖。想在編輯器外的終端機使用，可以在設定中「複製註冊指令」執行一次
- **AI 快速動作**（`Ctrl+J` 或在選取範圍按右鍵）：改寫得更精簡、修正錯字、翻譯、摘要，也可以直接輸入指示；動作與提示詞可以在設定中自訂。背後執行 `claude -p`（或 `codex exec`），AI 只處理選取的文字，不能執行命令、不能讀寫檔案，完成後顯示用量。用 Codex 時需要 0.59.0 以上的版本（舊版無法關掉執行命令的工具，會直接提示更新）；你自己在 Codex 設定檔加的 MCP 伺服器仍然會載入
- **外部修改逐段標示**：AI 在終端機裡直接改了已開啟的檔案時，標示改了哪些地方，可以逐段還原；連續修改會以第一次修改前的內容為基準
- **GitHub Actions 的 Claude Code**（指令面板「Git：加入 Claude Code 自動校對」）：在 Git 儲存庫建立 `.github/workflows/claude.yml`（使用 [claude-code-action](https://github.com/anthropics/claude-code-action)）。推送到 GitHub 後，開 PR 修改文件時 Claude 會用台灣繁體中文校對、在 PR 上留言建議（不直接改檔案）；在 issue 或 PR 留言寫「@claude 請幫我……」，Claude 會照著做，需要時開 PR。需要在 GitHub 儲存庫設定一次 `CLAUDE_CODE_OAUTH_TOKEN`（建立後可以直接在終端機執行 `claude setup-token` 取得），或在 Claude Code 裡執行 `/install-github-app` 自動設定

### 傳給 ChatGPT（預設關閉）

在「設定 → AI 協作 → 傳給 ChatGPT」選「ChatGPT 桌面版」或「網頁版（chatgpt.com）」開啟，和上面的 AI 協作開關無關，網頁版 oMarker 也能用（一律開網頁版）。內容會送到 OpenAI 的 ChatGPT，公司的文件、Wiki、工作項目請先確認公司規定允許再傳；第一次使用會先跳出提醒，按「傳給 ChatGPT」後就不再問。

- **在哪裡**：在原本的「複製…」旁邊多一項「傳給 ChatGPT」：編輯器與預覽選取文字的右鍵選單（沒有選取時不顯示）、Wiki 頁面與工作項目分頁的「複製成 Markdown 文件」下面、Wiki 修改紀錄的「複製這一版的內容」旁邊、Wiki 衝突的「複製我的完整版本」旁邊。路徑、提交編號、連結、複製成圖片不會有這一項
- **怎麼傳**：把內容帶進 ChatGPT 的輸入框，由你自己按送出。桌面版開 `codex://new?prompt=…`，網頁版開 `https://chatgpt.com/?q=…`；網址由原生端組，只接受這兩種，而且要和設定選的一樣
- **桌面版沒有官方保證**：ChatGPT 桌面版沿用 Codex 的網址，OpenAI 沒有保證一直能用；打不開或沒帶進內容時，請在設定改用網頁版。沒偵測到 ChatGPT 桌面版時，設定裡的桌面版選項不能選
- **內容太長時**：網址放不下（編碼後超過 2000 個字元）時，先把內容複製到剪貼簿，再開 ChatGPT（網頁版不帶內容，桌面版只帶「以下是內容：」），請在 ChatGPT 按 `Ctrl+V` 貼上

編輯器 MCP 伺服器提供的工具：`get_active_document`、`get_selection`、`list_open_documents`、`read_document`、`propose_edit`、`propose_replace_selection`、`run_command`、`list_terminals`、`read_terminal_output`。

自己編譯（需要 Windows，以及 [開發與架構「開發環境」](development.md#開發環境)列的工具）：

```sh
cd web && npm install && npm run wasm && npm run build
cd ../desktop && cargo build --release   # 產生 desktop/target/release/md-editor.exe
```

開發時可先在 `web/` 執行 `npm run dev`，再於 `desktop/` 執行 `cargo run --no-default-features`，桌面視窗會直接連到開發伺服器、即時更新。
