# 輸入法測試清單

輸入法問題自動化測試抓不到全部，每次發布前請在 **Windows 桌面版（omarker.exe）** 手動跑一遍，並把結果記在該次的 issue 或 PR 裡。

## 開發規則

所有自訂的按鍵處理，都要在組字中直接放行，不做任何事：

- DOM 事件：檢查 `event.isComposing`（全域快速鍵、指令面板、檔名欄位已遵守）
- CodeMirror 指令：檢查 `view.composing`（表格的 Tab／Enter 已遵守）
- 不要在組字進行中修改游標附近的文件內容或裝飾；要補字請等 `compositionend` 之後（參考 `web/src/brackets.ts`）

## 要測的輸入法

| 輸入法 | 設定 |
| --- | --- |
| 微軟注音 | 新版（預設） |
| 微軟注音 | 「使用舊版微軟注音」相容模式 |
| 微軟倉頡 | 預設 |
| 小狼毫（Rime） | 預設（選用） |

## 測試項目

每個輸入法都跑一次。打勾代表正常，不正常的請記下現象並開 issue。

### 一般輸入

- [ ] 在段落中連續輸入一整句中文，沒有漏字、重複字
- [ ] 第一個字不會遺失（尤其是剛開啟檔案、預覽正在更新時）
- [ ] 輸入全形標點 `，。、；：？！`，一次就出現，不需要按兩次
- [ ] 選字視窗出現在游標附近，不會跑到畫面角落
- [ ] 輸入到一半按 `Esc` 取消組字，文件沒有殘留

### 括號自動配對

- [ ] 輸入「 會自動補上 」，游標在中間
- [ ] 接著打字後再輸入 」，不會出現兩個 」
- [ ] 先選取一段文字再輸入「，會把文字包起來
- [ ] 在詞的中間輸入（ 時不會自動補 ）
- [ ] 設定中關閉「自動補上右括號與引號」後，以上行為都停止

### 清單、引言、表格

- [ ] 在清單項目（`- `）中輸入中文並按 Enter 選字，不會意外產生新的清單項目
- [ ] 選字後再按 Enter，才會延續清單
- [ ] 在引言（`> `）中輸入正常
- [ ] 在表格儲存格中輸入中文，選字時按 Tab／Enter 只會選字，不會跳格或新增列
- [ ] 選完字後按 Tab，會跳到下一格並對齊表格

### 其他輸入框

- [ ] 指令面板（`Ctrl+Shift+P`）中輸入中文搜尋，選字時按方向鍵與 Enter 不會執行指令
- [ ] 檔名欄位輸入中文檔名，選字時按 Enter 不會提前結束編輯
- [ ] 設定對話框、搜尋與取代面板中輸入中文正常

### 快速鍵

- [ ] 組字中按 `Ctrl+B`、`Ctrl+S` 不會造成文字遺失
- [ ] 組字結束後快速鍵正常

## 已知的上游問題

以下問題不是本專案造成的，遇到時請記下 WebView2 版本（設定 → 應用程式 → Microsoft Edge WebView2 Runtime）：

- WebView2 回報 #5625：渲染程式忙碌時，第一個中文字遺失、標點重複
- CodeMirror 論壇回報：微軟拼音輸入標點時需要按兩次

## 自動化測試涵蓋的範圍

瀏覽器端對端測試用 Chrome DevTools Protocol 模擬組字（`Input.imeSetComposition`＋`Input.insertText`），已涵蓋「括號配對」的四個情境。實際輸入法的選字行為、選字視窗位置，仍需要以本清單手動驗證。
