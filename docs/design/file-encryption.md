# 檔案加密（設計筆記，討論中）

> 狀態：**還沒決定，先記下來**。方向已經確定是「金鑰綁在 Windows 帳號、不用密碼」，圖示與幾個細節還在想。決定後再依這份筆記實作。

## 目的

- 在自己的電腦、用自己的 Windows 帳號：加密檔打開和一般檔案一樣，**不用輸入任何密碼**。
- 檔案被帶走（複製到隨身碟、寄出去、放到別台電腦或別的 Windows 帳號）：**打不開**；用記事本等其他程式打開只看得到說明文字和亂碼。

防的是「檔案離開這台電腦」，不是「每次打開都要驗證」。

**防不了的**（說明文件要寫清楚）：
- 已經登入你 Windows 的人（直接用你的電腦）。
- 用你的帳號在執行的惡意程式。
- Windows 帳號沒有設密碼或 PIN 時，拿走硬碟的人也可能取得金鑰。

## 金鑰

| 金鑰 | 怎麼產生 | 放在哪裡 |
|---|---|---|
| **電腦金鑰** | 第一次加密時，用作業系統的密碼學亂數產生 256 位元（`ring::rand::SystemRandom`，Windows 上是 `BCryptGenRandom`） | Windows 認證管理員（和 Azure DevOps 的 PAT 同一個地方，由 Windows 用帳號保護）；只在 Rust 後端，介面拿不到 |
| **檔案金鑰** | 每個檔案加密時各自隨機產生 256 位元 | 用電腦金鑰「包起來」（AES-256-GCM 加密）放在檔頭 |
| **復原金鑰** | 就是電腦金鑰本身，顯示成 `XXXX-XXXX-…` 分組文字 | oMarker 不另外保存；第一次加密時顯示，之後可以在選單「顯示復原金鑰…」再看 |

- 內容用檔案金鑰加密：AES-256-GCM，每次存檔產生新的 12 位元組 nonce；GCM 的驗證碼能偵測竄改。
- 為什麼多一層檔案金鑰：之後要加「另外設密碼」或換電腦金鑰時，只要重新包檔頭那 32 位元組，不用重新加密內容。
- 記憶體裡的金鑰放在離開範圍就覆寫成 0 的型別（`zeroize`）。

## 檔案格式（草案）

整個檔案是純文字，網路磁碟、Git 都能正常處理：

```
這是 oMarker 加密的檔案，請用 oMarker 開啟。
This file is encrypted by oMarker. Open it with oMarker.

-----BEGIN OMARKER ENCRYPTED FILE-----
Version: 1
Key: machine
（base64：包好的檔案金鑰、nonce、加密後的內容）
-----END OMARKER ENCRYPTED FILE-----
```

## 什麼情況要用復原金鑰

- 重灌 Windows、換新電腦。
- 公司 IT 重設你的 Windows 密碼（不是自己改密碼）時，Windows 保護的資料可能遺失。
- 想在公司和家裡兩台電腦都打開：在另一台電腦輸入一次復原金鑰，之後那台也能直接打開所有加密檔。

## 畫面流程（已做過示意）

1. **入口**：分頁、檔案樹的右鍵選單和指令面板，多一項加密的動作（名稱待定，見下面）。
2. **第一次加密（說明）**：金鑰存在這台電腦的 Windows 帳號、不用密碼；在這台電腦打開和平常一樣；帶到別台電腦、別的帳號打不開；檔名會改、搜尋和 AI 不讀這個檔案；Windows 帳號要設密碼或 PIN。
3. **復原金鑰（只有第一次）**：大字分組顯示，可以複製、另存成文字檔、列印；要勾「我已經把復原金鑰收好了」才能完成。
4. **之後再加密**：一個確認視窗就好。
5. **在自己的電腦打開**：和一般 Markdown 一樣（即時預覽、編輯）；狀態列的標記點開是選單：取消加密、顯示復原金鑰、在其他電腦打開。
6. **在別台電腦打開**：分頁裡顯示「這台電腦沒有這個檔案的金鑰」，輸入復原金鑰、按「加入這台電腦」。
7. **用記事本打開**：只看得到最上面兩行說明和一段亂碼。

## 會留下明文的地方，加密檔要另外處理

| 地方 | 處理 |
|---|---|
| 草稿、未存檔內容（WebView 的 localStorage） | 由後端用同一把金鑰加密後才存 |
| 關閉的分頁（`Ctrl+Shift+T`） | 同上 |
| 本機版本記錄 | 版本也加密 |
| 全文搜尋、待辦、標籤、反向連結 | 跳過加密檔 |
| AI 功能（MCP、送到終端機的 AI） | 預設不能讀加密檔 |
| 貼上的圖片（另存成圖片檔） | 第一階段先提醒；第二階段改成嵌在加密檔裡 |
| 匯出 PDF／Word、複製 | 使用者自己的動作，允許 |
| Git | 之前提交過的版本仍是明文：加密前提醒 |

## 還沒決定的事

1. **圖示**：看過的方向，使用者都還不滿意。
   - 線條圖示：鎖頭、檔案加鎖、盾牌加鎖、空白檔案（無字天書）、檔案＋電腦徽章、螢幕裡一把鎖……
   - 其他做法：「密」字紅印章取代檔案圖示、檔名後面加文字標籤「本機」、封條、黃色小鎖（像 Windows 加密檔）、整列換底色、只用文字。
   - 注意：空白檔案圖示（`file`）已經用在 `Ctrl+P` 的非文件檔案，不能直接拿來當加密檔。
2. **文字**：強調「綁在這台電腦」時，動作叫「鎖在這台電腦…」、狀態列寫「只限這台電腦」；或維持「加密這個檔案…」「已加密」。
3. **原本的明文檔**：建議加密後直接刪掉、不放資源回收筒（否則明文還留在回收筒）。
4. **檔名**：`週報.omd`，或保留原本副檔名的 `週報.md.omd`。
